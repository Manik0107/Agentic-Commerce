Three walls, three components
01 · CATALOG LAYER

Agents cannot read merchant catalogs

The merchant's own feed says Kurti - Ladies, Navy Blu, cottn.

Four tiers — cache, synonym, Gemini, difflib — map it to a canonical taxonomy, each seeing only what the tier above could not answer. Hierarchical, so Navy Blu keeps both blue and navy. Every value scored. Discovery is one link tag.

02 · PROTOCOL ADAPTER

Agents speak different protocols

AP2, ACP and x402 each say "I want to buy this" differently.

One translator turns any dialect into a single internal Order Intent, and the answer back. AP2 both ways; ACP and x402 declared, and they raise rather than pass half a message on. A refusal returns as a protocol decline, never a transport error.

03 · PAYMENT GATE

An agent that can pay can overspend

Nothing in the protocol bounds what an agent does with payment authority.

It holds a token the user scoped: spend cap, merchant, category, expiry. The gate checks all four in that order, and any failure blocks with no partial charge. Money is integer paise end to end.

What the gate guarantees
01

A blocked attempt cannot charge

Not "does not" — cannot. Every refusal returns before control reaches the processor call, so no ordering bug or later edit can charge a refused intent.

02

Two agents cannot both fit one cap

Check and reserve happen inside one BEGIN IMMEDIATE transaction. The tests race two threads at one cap and exactly one gets through.

03

Every attempt is audited, crashes included

The audit write sits in a finally. A trail of only the paths that went well proves nothing about whether anyone was protected.
